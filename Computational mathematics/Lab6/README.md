# Лабораторная работа №6 — вариант 15

React (JavaScript) + Java, Jakarta Servlet 6.0, WildFly. Без Spring Boot и сторонних вычислительных библиотек. Gradle собирает фронтенд и бэкенд в **один `lab6.war`**.

## Запуск одной командой

```bash
bash run.sh
```

Скрипт проверяет окружение, запускает Gradle `:app:check :app:war`, разворачивает WAR и поднимает WildFly. После готовности приложение доступно по адресу **http://localhost:8180/lab6/**. Для остановки нажмите `Ctrl+C` в том же терминале.

Нужны JDK 17+, Node.js 22.12+ (или 20.19+), npm и WildFly 27+ с Jakarta Servlet 6.0. Проект проверяется на установленном WildFly 39. При первой сборке нужен доступ к Maven Central и npm.

WildFly автоматически находится в стандартных путях Homebrew и `/opt/wildfly`. Другой путь:

```bash
WILDFLY_HOME=/path/to/wildfly bash run.sh
```

Для другой группы портов:

```bash
PORT_OFFSET=200 bash run.sh
```

HTTP-порт равен `8080 + PORT_OFFSET`; по умолчанию сдвиг 100 и порт 8180. Управление: `9990 + PORT_OFFSET` (10090 по умолчанию). Сервер слушает только `127.0.0.1`. WildFly 26 с `javax.servlet` несовместим с этим WAR.

Скрипт создаёт отдельный экземпляр в `.wildfly/`: конфигурацию, deployment, временные файлы и журналы. Общая установка WildFly и другие лабораторные не меняются. Журнал запуска: `.wildfly/log/console.log`; журнал сервера: `.wildfly/log/server.log`. Если запуск был аварийно прерван, убедитесь, что экземпляр остановлен, и удалите пустой каталог `.wildfly/run.lock` перед повторным запуском.

## Сборка WAR без запуска

```bash
./gradlew :app:war
```

Результат: `app/build/libs/lab6.war`. В нём находятся:

- `index.html` и `assets/` — собранный React;
- `WEB-INF/classes/` — Java-сервлет и численные методы;
- `WEB-INF/web.xml` и `WEB-INF/jboss-web.xml` — настройки приложения и контекст `/lab6`.

Servlet API предоставляет WildFly, поэтому эта библиотека не включается в WAR. Отдельный сервер Node.js при работе приложения не нужен.

## Проверки

```bash
./gradlew :app:check
```

Тесты проверяют первые шаги методов, порядок сходимости, правило Рунге по совпадающим узлам, аналитические решения, все 9 сочетаний уравнений и методов, запятую, научную запись, разрыв решения, ограничения сетки и недостижимую точность. JUnit используется только в тестах. Дополнительно проверяются числа с более чем 300 десятичными знаками, сообщения об ошибках и масштаб графика при предельных значениях double. Проверка оси на Node.js также входит в Gradle `check`.

## Возможности

- Три ОДУ: `y′ = y − x² + 1`, `y′ = cos(x)`, `y′ = y²`.
- Методы варианта 15 (1, 3, 4): Эйлер, Рунге–Кутта 4, Адамс (предиктор–корректор).
- Вариант 15 закреплён в интерфейсе: всегда рассчитываются все три метода; чужие методы удалены из Java и React.
- Ввод `x₀`, `xₙ`, `y₀`, `h`, `ε`; поддержка точки, запятой и экспоненциальной записи.
- Уменьшение шага, графики решения и ошибок, приближение выделенной прямоугольной области по обеим осям, возврат к полному графику и включение кривых.
- Таблицы всех узлов каждого метода, полное представление double, экспорт всех результатов в CSV и графика в SVG.
- Три готовых примера исходных данных.

Ввод не ограничивается числом десятичных знаков. Арифметика — Java `double`: после разбора возможна обычная для IEEE 754 потеря точности. Числа вне диапазона, слишком малая ε и неразличимые узлы сопровождаются сообщениями. Максимум 131 072 шага на метод.

## Контроль точности

На начальной сетке `N = ceil((xₙ−x₀)/h)`, фактический `h = (xₙ−x₀)/N`. При наличии многошаговых методов берётся минимум четыре интервала. Правая граница включается точно, короткого последнего шага нет.

Для одношаговых методов сравниваются решения на сетках `N` и `2N`: `R = max |yʰᵢ − yʰ⁄²₂ᵢ| / (2ᵖ−1)`. При достижении ε возвращается более мелкая сетка. Это оценка погрешности, а не строгая гарантия; фактическая ошибка относительно точного решения показывается отдельно.

Для Адамса первые три шага вычисляются RK4, затем выполняется прогноз и итерационная коррекция. Остановка корректора: изменение не превышает `max(ε/(100·(N+1)), 4·ulp(y))`; максимум 100 итераций. При несходимости весь расчёт повторяется с половинным шагом. Глобальная точность проверяется по `max |yᵢ − yточн(xᵢ)|` на всех узлах. Все методы уточняют собственную равномерную сетку независимо.

## Структура

`app/src/main/java/ru/itmo/ode/`: `ApiServlet` — HTTP, `Input` — валидация, `Equation` — уравнения и точные решения, `NumericalMethods` — формулы, `Solver` — сетка и контроль ошибки, `Json` — сериализация ответа. `frontend/src/` — React-интерфейс.
